Background

Coding agents now ship as harnesses

A harness wraps a model in capabilities that persist and compose across turns, agents, and sessions.

R
Persistent execution

A live Python namespace the agent keeps working in, turn after turn.

S
Recursive delegation

Child agents spawned like function calls, for parallel or background work.

M
Durable state

Memories, skills, and refinements that outlive a single session.

Each capability adds prompt surface, tokens, and failure modes. They are added together, benchmarked together, and justified by one aggregate score — which cannot say which part earned it.
Testbed

An RLM-style harness with a continual memory

Recursive Language Model

Context lives in variables and sub-agents are function calls, all inside one persistent Python REPL.

>>> rows = open("orders.csv").read() # context as data >>> job = rlm.spawn(…) # a sub-agent as a call >>> rlm.collect(…) # results as values

Continual harness

Supplemental prompts, memories, skill descriptions, and sub-agent specs persist as durable state, refined by small, evidence-backed updates.

Memoriesfacts and conventions
Skill descriptionsreusable workflows
Supplemental promptsnever the base prompt
Sub-agent specsrefined via /refine, with rollback
The study turns three of these into switches: R the REPL namespace persists S rlm.spawn may create children M harness state is read and refined

Instrument: Prime Agent, an open-source coding agent (Rust, daemon-supervised workers). The study names it only for reproducibility — the claims are about harness components, not the product.

Research question

Which capability pays for itself — on what kind of task, and at what cost?

R
Persistent execution
On
The REPL namespace survives each settled turn.
Off
Cleared after every turn; within-turn execution unchanged.
S
Recursive delegation
On
The agent may spawn child agents.
Off
Child admission is refused at the host boundary.
M
Durable state
On
Harness state is read, injected, and refined.
Off
A pinned empty harness; writes are refused.
Design expectation — each task family stresses one factor: I · information management → R E · engineering → S T · cross-episode transfer → M
Design

A 2 × 2 × 2 factorial: eight harnesses from one codebase

r1-s1-m1 is the shipped product; r0-s0-m0 turns every capability off.
Same model, prompt layers, tools, compaction, fixtures, verifier, and per-cell request quota in every arm.
Paired blocks: every task instance runs under all eight treatments, in a fixed order.
A stable treatment ID is written into every record; an unknown ID fails the run instead of silently running the full product.
Method · treatment layer

Each switch lives where the capability is admitted

Roff

A TurnEnd hook calls the kernel's reset_namespace: user bindings are cleared, runtime bindings (rlm, bash, asyncio) kept. A failed reset fails the run.

Kernel protocol + session engine
Soff

The child host is withheld, allow_recursion is forced false, and the spawn capability leaves the system prompt; the kernel answers “no RLM child runtime”.

Session wiring + layered system prompt
Moff

The experiment's agent directory pins the harness gate off: no digest is injected, the refine skill is removed, and direct writes are refused.

Agent directory settings + skill inventory

Deployment-safe

The CLI has no treatment flag. Experiments set PRIME_AGENT_HARNESS_TREATMENT; the product path always resolves r1-s1-m1.

Checked where the model sees it

R off: a value set last turn reads missing
S off: a counting host records zero spawns
M off: create_memory is refused
All eight IDs built in one matrix test
Method · measurement

Every cell is metered, verified, and accounted for

Counted · agent failures

  • Wrong or partial answer
  • Request budget exhausted

Retried · infrastructure

  • Transport errors
  • Timeouts

The accounting rule

A cell's outcome is its first attempt that completed or exhausted its quota. Protocol hashes are frozen before the main run; records are resumable JSONL.

Main matrix, after the audit: 1,168 attempts→720 counted cells 447 infrastructure retries 1 budget-exhausted cell counted, its retry discarded
Experiments · task suite

Three families, three probes, four public benchmarks

Iprimary: R
Information management

Three joined tables (orders, customers, refunds), a date window, weekday aggregation, a contradiction count. Six checked fields.

Eprimary: S
Engineering

An orders package with six independent defects. Verifier-owned hidden tests; score = pass ratio (reference fix 7/7, unmodified 0/7).

Tprimary: M
Transfer

Three-episode series: episode 1 states a rule, episodes 2–3 withhold it. Ten templates — six keep the rule, four change a threshold.

Probes

  • Mechanism — arbitrary per-instance thresholds, never repeated
  • Boundary — every row within 2 bp of a threshold
  • Hidden policy — a non-derivable code→queue table, 3/6/12 episodes

Public benchmarks

  • LongBench-v2 · 20 long-context questions
  • SWE-bench Verified · 12 repositories
  • LongMemEval · 10 memory questions
  • OOLONG · 11 lengths, 1k → 4M tokens

Models

  • deepseek-v4-flash — every run
  • deepseek-v4-pro — replication on transfer and LongMemEval

30 instances per family, each run under all eight treatments → 720 main-matrix cells. Probes and benchmarks use the arms that isolate the factor they test.

Result 4 · the pilot

A large pilot effect did not survive ten templates

Mechanism check · 40 cells. Arbitrary thresholds, never repeated after episode 1; fresh HOME and TMPDIR for M-off. Accuracy 40/40 — but M-off needs 22–27 requests per series vs 14–20 with memory.
Boundary check · 20 cells. Every row within 2 bp of a threshold. At ceiling with an 80-request quota; under the original 40, M-off 7/10 (M-on 10/10).

If the rule can be recovered from the inputs, memory buys cheaper work, not better answers.

Result 6 · the exception

When durable state does pay

Hidden-policy probe. Twelve opaque codes map to queues through a table stated once, never written to a readable file, and not inferable from the codes.
0.936 vs 0.455
M-on vs M-off · 95% CI of the gap [0.37, 0.61]
Stronger model. deepseek-v4-pro does not reconstruct withheld conventions: full 0.975 vs all-off 0.710 (CI [0.08, 0.47]), and all-off costs 4.5× (¥11.24 vs ¥2.50).
Small samples (6 vs 4 cells; 10 per arm), and the strong-model run contrasts full vs all-off — it does not isolate M.
Synthesis

The harness contract, restated

Must the state survive across episodes?   no → yes
re-derivable · cross-episode
Capabilities buy cheaper repeated work
Transfer family and mechanism check: same accuracy, ~2× spend without memory.
not derivable · cross-episode
Durable state buys accuracy
Hidden-policy probe: 0.936 vs 0.455. A stronger model re-derives less, so tasks drift here (0.975 vs 0.710).
re-derivable · within an episode
Cost differences only
I and E families: R off adds 34–41% requests at unchanged accuracy. OOLONG to 4M tokens is solved either way.
not derivable · within an episode
The prompt carries it
Nothing needs to persist, so no capability is required to deliver it.
Can the state be re-derived from the task's inputs?   yes → no
Budget-aware selection over all 512 per-family policies (in-sample):
¥16.87 · 0.991
The shipped default is already on the cost frontier. The best mix reaches 0.998 for ¥25.98 — +54% spend for ≤ 0.7 points.

A selector here would be predicting cost, not accuracy.

Takeaways

Three things to remember

1

On tasks whose state can be re-derived, the harness changes cost, not accuracy. The full harness is the cheapest arm (¥16.87 vs ¥32.27), and transfer accuracy is bounded within about two points.

2

Durable state turns into accuracy when the state cannot be derived and must persist (0.936 vs 0.455) — and when the model cannot reconstruct it (0.975 vs 0.710).

3

Measurement discipline is part of the result. Failure accounting, budgets, and isolation all moved the bounds — so they get fixed before the study scales.
