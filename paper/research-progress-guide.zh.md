## 先看懂主线（30 秒版）

1. 现在的编码 agent 不只是一个模型，而是"模型 + 一套能力外壳"，英文叫 **harness**。
2. 我们把外壳里的三项能力做成开关：**R 持久执行、S 子 agent、M 持久记忆**。三个开关组合出 8 种配置，在同一批任务上逐一比较。
3. 结果：**准确率几乎不变，花费却差一倍**，而且所有能力全开反而最便宜。
4. 例外：如果需要的信息**无法从输入里推出来，又必须跨会话保留**，记忆能把准确率从 0.455 提到 0.936。
5. 本周的审计查出并修正了几处计分和流程问题。下一步是补漏洞、把正面结果做扎实，然后投稿。

## 术语速查

| 术语 | 意思 | 打个比方 |
|---|---|---|
| **harness** | 包在模型外面的工作环境和能力：能跑代码、能派帮手、能记笔记 | 同一个厨师（模型），配不同的厨房 |
| **R · 持久执行** | Python 里的变量在两轮对话之间保留 | Jupyter 不重启，算过的数据还在 |
| **S · 递归委派** | agent 可以派出子 agent 去做一部分工作 | 经理能把活分给下属 |
| **M · 持久状态** | 记忆、技能、规则可以跨会话保存，并被改进 | 一本随身笔记本 |
| **配置 / arm / treatment** | 三个开关的一种组合，共 8 种 | 8 种厨房配置 |
| **`r1-s1-m1`** | 配置编号，1 = 开，0 = 关。`r1-s1-m1` 是全开（产品默认），`r0-s0-m0` 是全关 | — |
| **任务实例 instance** | 同一类任务里的一道具体题目 | 一道题 |
| **格 / cell** | 一个实例在一种配置下的一次计分运行 | 一张答卷 |
| **主实验 main matrix** | 3 个任务族 × 30 个实例 × 8 种配置 = 720 格 | 正式考试 |
| **预实验 pilot** | 正式实验前的小规模试跑（120 格） | 模拟考 |
| **episode / 轮** | T 族里一次独立的会话。一个系列有三轮 | 三次分开的上课 |
| **天花板效应** | 题太简单，所有配置都接近满分，看不出差别 | 考试太简单，学霸和普通学生都考满分 |
| **配额 / quota** | 每格最多允许发多少次 API 请求 | 每道题限时、限草稿纸 |
| **预算代理 budget proxy** | 夹在 agent 和 API 之间，负责计数、拦截超额请求、统计花费 | 收银台 |
| **Fisher 精确检验** | 检验两组成功率是否有显著差异。p 越大，越看不出差异 | — |
| **bootstrap 置信区间** | 反复重新抽样，估计差值可能落在的范围。95% CI 就是这个范围 | — |
| **等价检验 / 等价界** | 不只说"不显著"，而是证明差异小于事先定好的阈值（这里是 ±2 分） | — |
| **MDE · 最小可检测效应** | 以当前样本量能可靠测出的最小差距 | 尺子的最小刻度 |
| **分（point）** | 0.01 的得分差。"2 分"就是 0.02 | — |
| **可推导** | 规则能不能从输入数据本身推回来 | 题目里有没有足够线索 |
| **基础设施失败** | 网络错误、超时这类不怪 agent 的失败，应当重跑 | 考场停电 |
| **agent 失败** | 答错，或用完了预算，应当如实计分 | 答错或没写完 |
| **deepseek-v4-flash / -pro** | 便宜模型（所有实验都用）/ 强模型（只做复现） | — |
| **¥** | 调用 API 实际花的钱（人民币） | — |

**页面内容：**

- **副标题**：持久执行、递归委派、持久状态各自花多少钱，什么时候值得。
- **三个标签**：
  - **1,222 个计分格**：所有实验加起来的有效运行次数。
  - **8 种配置**。
  - **初稿完成、审计修正已应用**。
- **右边的开关面板会自己动**：R、S、M 三个开关轮流切换 8 种配置，下面两条进度条显示该配置在主实验里的成绩。
  - 准确率条：90 格里做对多少格，始终在 83–88 之间，几乎不动。
  - 花费条：每 90 格的花费，在 ¥16.87 到 ¥32.27 之间来回大幅摆动。

**可以这么说：**
> "这个研究在给 agent 的能力记账。右边这个面板在轮流关掉不同能力，你会看到上面的准确率几乎不动，下面的花费来回摆，最贵的配置差不多是最便宜的两倍。"

### 第 3 页 · 背景：现在的编码 agent 都是"外壳"

**这页在说什么：** 为什么需要这项研究。

**页面内容：**
- 一句话定义：harness 把模型包在一组能力里，这些能力能**跨轮、跨 agent、跨会话**地保留和组合。
- 三项能力（按 `→` 逐条出现）：
  - **R · 持久执行**：agent 在一个一直存活的 Python 环境里工作，变量一轮一轮保留下来。
  - **S · 递归委派**：可以像调用函数一样派出子 agent，并行或在后台干活。
  - **M · 持久状态**：记忆、技能和改进，能比一次会话活得更久。
- **问题框**：每项能力都会多占提示词、多花 token、多带来出错的可能。但它们总是**一起加进来、一起评测、用一个总分来证明有用**。总分没法告诉你是哪个部分的功劳。
- **右边的圆环图**：中间黑圈是模型，外面三圈是 R、S、M，箭头指向"一个分数"，下面的问号问"是哪一圈的功劳？"

**可以这么说：**
> "大家现在评测 agent，都是整套系统一起打分。分数高了，你说不清是哪个零件的功劳，也不知道哪个零件在白花钱。"

**可能被问：** 为什么不直接看 SWE-bench 这类基准的分数？
> 那是"模型 + 整套 harness"的总分，拆不开。我们要的是每个零件单独的贡献。

### 第 4 页 · 测试平台

**这页在说什么：** 研究是在哪个系统上做的，以及它的两个核心设计。

**页面内容：**
- **左卡 · Recursive Language Model（RLM）**：上下文放在变量里，子 agent 当函数调用，全部在一个持久的 Python 环境里完成。三行示例代码：
  - `rows = open("orders.csv").read()`：把文件内容读进变量，"上下文就是数据"。
  - `job = rlm.spawn(…)`：派出一个子 agent，"子 agent 就是一次函数调用"。
  - `rlm.collect(…)`：取回子 agent 的结果，"结果作为值返回"。
- **右卡 · Continual harness（持续改进的外壳）**：四类可以长期保存的东西。
  - 记忆：事实和约定。
  - 技能描述：可复用的做事流程。
  - 补充提示：只补充，从不改基础提示词。
  - 子 agent 规格：通过 `/refine` 改进，可以回滚。
- **中间灰条**：这三项被我们做成了开关。R 对应变量能否保留，S 对应 `rlm.spawn` 能否派子 agent，M 对应外壳状态能否读写。
- **最下面一行**：实验平台是 Prime Agent（开源，Rust 实现）。点名只是为了可复现，结论讲的是 harness 组件，不针对某个产品。

**注意：** 论文本身是匿名的。如果在匿名评审期间对外讲，建议把这句里的名字删掉。

### 第 6 页 · 实验设计：2 × 2 × 2

**这页在说什么：** 三个开关各有开和关，组成 8 种配置，每道题在 8 种配置下都跑一遍。

**图怎么看（立方体）：**
- 8 个顶点就是 8 种配置。
- 沿底边向右是 R 从关到开，竖着向上是 M，斜着往里是 S。
- **橙色点 `r1-s1-m1`** 是全开，即产品默认；**蓝色点 `r0-s0-m0`** 是全关。
- 相邻两个顶点只差一个开关。虚线是立方体背面被挡住的边。

**右边四条要点：**
1. `r1-s1-m1` 是正式产品，`r0-s0-m0` 是全部关掉。
2. 除了开关，其他条件完全一样：同一个模型、同样的提示词层、工具、上下文压缩策略、题目、评分器，以及每格的请求上限。
3. **配对设计**：每道题都在 8 种配置下各跑一次，顺序固定。这样配置之间的差别不会被"题目难易"干扰。
4. 每条记录都写上配置编号；如果编号写错，实验会直接报错，而不会悄悄按全开去跑。

**可以这么说：**
> "这是一个全因子实验：同一道题让 8 种配置都做一遍，差异只能来自开关。"

### 第 7 页 · 开关是怎么实现的

**这页在说什么：** 开关装在能力"被放行"的那一层，而不只是在提示词里叮嘱一句"别用"。

**为什么要强调：** 只在提示词里说"不许用子 agent"，模型可能照样调用，消融就不干净。开关必须装在系统入口。

**页面内容：**
- **R off**：每轮结束时，系统调用内核的 `reset_namespace`。用户自己的变量全部清空，系统自带的工具（`rlm`、`bash`、`asyncio`）保留。清空失败，这次运行直接判失败。
- **S off**：三道关同时生效。
  - 不给会话接上"子 agent 宿主"。
  - 把 `allow_recursion` 强制设为 false。
  - 从系统提示里删掉"可以派子 agent"这项能力。
  - 如果模型硬要调用，内核回复 "no RLM child runtime"。
- **M off**：实验用的配置目录把外壳功能锁死为关。不注入记忆摘要，删掉 refine 技能，任何直接写入都被拒绝。
- **右上 · 不影响正式产品**：命令行没有开关参数；实验只能通过环境变量 `PRIME_AGENT_HARNESS_TREATMENT` 选择配置；正式产品永远是全开。
- **右下 · 在模型实际看到的层面验证过**：
  - R 关时，上一轮设的变量这一轮读出来是 `missing`。
  - S 关时，计数器记录到 0 次派子 agent。
  - M 关时，`create_memory` 被拒绝。
  - 8 种编号在一个测试里全部构建过。

### 第 8 页 · 测量流程

**这页在说什么：** 每一格怎么跑、怎么计费、怎么评分、怎么算成败。

**流程图（上排从左到右）：**
1. **Task fixture · 题目**：每道题实例化成一个独立目录。
2. **Agent under treatment · 按某种配置运行的 agent**，有独立的 HOME 和配置目录。
3. **Budget proxy · 预算代理**：每格有请求上限，有总花费闸门，网络失败最多自动重发 2 次。
4. **Provider API · 模型服务**：便宜模型和强模型。

agent 和代理之间的双向箭头表示请求发出去、结果返回来。橙色小点在线上流动，表示数据在走。

**下排：** agent 的答案交给 **Verifier · 评分器**（每个任务族自带，有隐藏测试，给 0–1 分），写成一条 **JSONL 记录**（用量、耗时、本格出过的错误），最后进入 **Analysis · 统计分析**（Fisher 检验、bootstrap 置信区间、等价检验、配置选择器）。

**三张卡片 · 计分规则（审计的重点）：**
- **算失败（agent 的问题）**：答错或只答对一部分；用完了请求预算。
- **重跑、不计入（基础设施的问题）**：网络错误、超时。
- **规则**：每一格的成绩，取它**第一次"跑完"或"用完预算"**的那次。

**为什么重要：** 网络错误重跑是公平的。但如果把"预算用完"也当成网络错误去重跑，就等于给效率低的配置开了"重考"机会，会悄悄抬高它的成绩。审计修的就是这个。

**底部灰条 · 主实验审计后的账目：**
- 一共尝试了 **1,168 次**，最终计分 **720 格**。
- **447 次**基础设施重跑：445 次网络错误，2 次超时。
- **1 格**用完了预算，现在按失败计入；它后来那次重跑作废。

### 第 9 页 · 任务设计

**这页在说什么：** 用了哪些题。

**三个任务族（上排）：**
- **I · 信息处理**（主要考 R）：三张关联表（订单、客户、退款），要按日期范围筛选、按星期汇总、统计矛盾记录，最后检查 6 个字段。
- **E · 工程 / 修 bug**（主要考 S）：一个订单处理代码包里藏了 6 个互相独立的 bug。用评分器自带的隐藏测试打分，得分是测试通过率。标准答案能过 7/7，原样代码 0/7。
- **T · 迁移**（主要考 M）：三轮系列，每轮是一次独立会话。
  - 第 1 轮告诉 agent 一条分类规则，比如工单分级的阈值，并让它记下来。
  - 第 2、3 轮不再给规则，只能靠记忆。
  - 10 个模板里，6 个规则不变（考正迁移），4 个在第 3 轮改了一个阈值（考会不会被旧记忆误导）。

**下排：**
- **三个探针**（专门设计的小实验）：
  - **机制检查**：把好猜的整数阈值换成任意值（比如 716 个基点），让规则猜不出来。
  - **边界检查**：每行数据都离阈值不到 2 个基点（bp，1 bp = 0.01%）。
  - **隐藏规则**：12 个无意义代码对应到队列的映射表，只在第 1 轮给一次，无法从代码本身推出来。系列长度有 3、6、12 轮。
- **四个公开基准**：
  - LongBench-v2：长文本选择题。
  - SWE-bench Verified：修真实 GitHub 项目的 bug。
  - LongMemEval：长期记忆问答。
  - OOLONG：超长上下文，从 1k 到 400 万 token。
- **模型**：所有实验都用 `deepseek-v4-flash`；`deepseek-v4-pro` 只在迁移任务和 LongMemEval 上做复现。

**最底下一行：** 每个任务族 30 道题，每道题在 8 种配置下都跑，所以是 720 格。探针和基准只用能单独考验目标能力的那几种配置。

### 第 11 页 · 结果 1：准确率几乎一样

**这页在说什么：** 8 种配置的准确率差不多。

**图怎么看：**
- 每根横条是一种配置在主实验 90 格里的做对比例，横轴 0–100%。
- **橙色**是全开，灰色是其余配置。
- 只标了三个数：全开 85/90（94.4%）、最低 83/90、最高 88/90。其他配置的数字鼠标停上去能看到，也可以按 `T` 看表格。
- 所有条子长度几乎一样。

**右边三张卡片：**
1. **83–88 / 90**：每种配置都做对 83 到 88 格，平均分 0.983–0.997。
2. **115 vs 116 / 120**：迁移任务族里，开记忆 115 格成功，关记忆 116 格。这组对比本来是专门用来考记忆的。Fisher 检验 p = 1.0，即完全看不出差异。
3. **接近天花板**：I 族每种配置都是 29/30，E 族 26–30，T 族 28–30。题太简单，所以 R 和 S 对准确率的影响在这套题上**测不出来**。

**可以这么说：**
> "8 种配置做对的题几乎一样多。但要注意，这主要因为题目太简单，大家都接近满分。"

**可能被问：** 准确率一样，是不是说明这些能力没用？
> 不是，有两个原因。一是题太简单，到了天花板。二是我们每格给了 40 次请求，预算很宽松。最新的事后分析发现，如果预算收紧到 20 次请求，迁移任务上开记忆能做对 62%，关记忆只有 10%。这还需要正式实验确认，详见文末"补充"一节。

### 第 12 页 · 结果 2：真正改变的是花费

**这页在说什么：** 能力的差别主要体现在钱上。

**左图 · 每种配置跑完 90 格的花费：**
- **橙色的全开最便宜：¥16.87。**
- 全关最贵：¥32.27，差不多两倍。
- 其余配置在两者之间，具体数字鼠标停上去能看到。

**右上图 · 关掉 R 之后，每格请求数增加了多少：**
- I 族 **+41%**，E 族 **+34%**，T 族 **+13%**。
- 原因：变量不能保留，agent 每轮都得重新读数据、重新算。

**右下卡片 · 没有记忆，迁移任务的花费约翻倍：**
- R 开时：¥17.19 对 ¥9.11。
- R 关时：¥22.93 对 ¥10.26。
- 原因：每一轮都要从头把规则重新推一遍。

**可以这么说：**
> "直觉上能力越多越贵，结果正好相反：全开最便宜。因为这些能力让 agent 更省事：变量保留免得重复计算，记忆免得每次重新推规则。"

### 第 13 页 · 结果 3：到底有多"一样"？

**这页在说什么：** "没测出差异"不等于"没有差异"，要给差异的大小划个上限。

**图怎么看（森林图）：**
- 横轴是"开记忆减关记忆"的平均分差，单位是分（1 分 = 0.01）。
- **圆点**是估计的差值，**横线**是 95% 置信区间，表示真实差值大概率落在这条线上。
- **灰色背景带**是事先定好的"等价范围" ±2 分：整条线都落在灰带里，才能说"两者等价"。
- **橙色 · 审计后**：差值 +0.6，区间 [-0.7, +2.2]。右端 +2.2 稍微超出了 +2，所以**严格说不能宣称等价**。图上标着 "+2.2 > +2"。
- **灰色 · 审计前**：差值 +0.2，区间 [-1.0, +1.5]，完全在灰带里。审计把一格"预算用完却被重跑"的成绩改回失败，区间就往右挪了一点。

**右边三张卡片：**
1. **能排除大于 2.2 分的差距**：记忆带来的好处不会超过 2.2 分，坏处不会超过 0.7 分。
2. **等价检验差一点没通过**：说明审计修正确实改变了结论的强度。
3. **55 / 60**：全开对全关的那组对比重复跑了一遍，60 格里 55 格分数完全一样。另外，公开基准每组只有约 20 题，只能测出 30 分左右的大差距。

**可以这么说：**
> "我们不只说'不显著'，而是给差异划了上限：记忆在迁移任务上的作用不超过 2.2 分。不过审计之后，严格的等价检验差一点没过。"

### 第 14 页 · 结果 4：预实验里的大效应没能复现

**这页在说什么：** 预实验里看到记忆作用很大，正式实验里消失了，以及为什么。

**图怎么看（哑铃图）：**
- 每一行两个点：**橙色是开记忆，蓝色是关记忆**，横轴是平均分 0–1。两点之间的线就是差距。
- **预实验**（1 个模板）：0.983 对 0.788，19/20 对 8/20，差距很大。
- **主实验**（10 个模板）：0.993 对 0.987，两个点几乎重合。为了让两个点都看得见，上下错开了一点。

**右边：**
- **机制检查（40 格）**：
  - 阈值换成猜不出来的任意值，第 1 轮之后不再出现；关记忆组每轮都换全新的 HOME 和临时目录，不能借文件偷偷传话。
  - 结果准确率 40/40 全对，但关记忆每个系列要 **22–27 次请求**，开记忆只要 **14–20 次**。
- **边界检查（20 格）**：
  - 每行数据都紧贴阈值。
  - 配额 80 次时全部满分；按原来的 40 次配额算，关记忆只有 **7/10**（开记忆 10/10），有 3 格没做完就用光了预算。
- **结论句**：只要规则能从输入数据里推回来，记忆省的是**功夫**，换不来**更对的答案**。

**可以这么说：**
> "单一模板的效应很脆弱，换成 10 个模板就没了。我们又追问了原因：只要数据本身就能反推出规则，没有记忆也能做对，只是要多花不少请求。"

### 第 15 页 · 结果 5：公开基准

**这页在说什么：** 换成公开基准，结论一致，但精度粗。

**左边表格（"启用"对"消融"）：**

| 基准 | 考什么 | 对比 | 启用 | 消融 |
|---|---|---|---|---|
| LongBench-v2 | 长文本选择题，5.7 万–17 万字符 | 全开 vs 全关 | 0.70 | 0.65 |
| SWE-bench Verified | 修真实项目的 bug | 全开 vs 全关 | 10/12 | 10/12（没修好的是同两个项目） |
| LongMemEval | 先读两轮材料，第三轮问答 | 开 vs 关记忆 | 11/20 | 12/20 |
| OOLONG | 超长上下文，最长 400 万 token，靠写脚本处理 | 开 vs 关 R | 11/11 | 11/11 |

下面那句话：每组只有约 20 题，只能发现 30 分左右的大差距。

**右上图 · 撞到原始配额的格子比例：**
- 这三个实验跑到一半时调高过请求配额，只把撞到上限的格子重跑了。这张图统计的是**调高之前**各配置撞上限的比例。
  - LongBench（原配额 8 次）：全开 0/20；三个关掉 S 的配置各有 4–5/20。
  - LongMemEval（原配额 90 次）：开记忆 0/20，关记忆 6/20。
  - 边界检查（原配额 40 次）：开记忆 0/10，关记忆 3/10。
- 规律：**撞上限的全是被关掉能力的配置。**

**右下卡片：** 按原始配额计分，消融组都落后：LongBench 0.55 对 0.70，LongMemEval 9/20 对 11/20。

**可以这么说：**
> "公开基准上没看到显著差距，但样本太小。有意思的是，预算一紧，掉队的总是被关掉能力的那组。"

### 第 16 页 · 结果 6：记忆真正有用的时候

**这页在说什么：** 唯一明确的正面结果。

**图怎么看（哑铃图，橙色是启用，蓝色是消融）：**
- **迁移 · 便宜模型**（全开 vs 全关）：0.988 对 0.990，两点重合，没有差距。
- **迁移 · 强模型**（全开 vs 全关）：0.975 对 0.710，差距明显。
- **隐藏规则探针**（开 vs 关记忆）：0.936 对 0.455，差距最大。

**右边卡片：**
1. **隐藏规则探针**：12 个无意义代码对应到队列的映射表，只说一次、不写进任何文件、也无法从代码推出来，所以只有记忆能把它带到后面的轮次。结果 0.936 对 0.455，差距的 95% 区间是 [0.37, 0.61]。
2. **强模型**：`deepseek-v4-pro` 关掉能力后，没能自己把规则重推出来，全关组还多花 4.5 倍的钱（¥11.24 对 ¥2.50）。
3. **注意事项**：样本很小（隐藏规则是 6 格对 4 格，强模型每组 10 格）；强模型那组是全开对全关，分不清是不是 M 的功劳。

**可能被问：**
- **隐藏规则探针是不是理所当然？信息只在记忆里，记忆当然有用。**
  > 对，它更像一个"阳性对照"：证明记忆开关真的起作用，也证明我们的测量在应该有差异的地方能测出差异。下一步要做"规则能推出多少"的梯度实验和真实场景任务，才能说明记忆在实际中的价值。
- **为什么强模型反而做得更差？**
  > 现在还不知道。过去的运行没有保存对话记录，下一步重跑时会保存，再分析原因。

### 第 17 页 · 综合：重新表述 harness 的价值

**这页在说什么：** 用一张 2×2 图把所有结果串起来。

**图怎么看：**
- **横轴**：所需的信息能不能从任务输入里推回来？左边能，右边不能。
- **纵轴**：这些信息要不要跨轮（跨会话）保留？下面不用，上面要。
- **四个格子：**
  - **左上（能推回来 · 要跨轮）**：能力换来的是更省的重复劳动。迁移任务和机制检查都是准确率一样，没有记忆约多花一倍钱。
  - **右上（推不回来 · 要跨轮）**：记忆换来的是准确率。隐藏规则探针 0.936 对 0.455；强模型自己重推得更少，所以它遇到的任务会往这一格移（0.975 对 0.710）。
  - **左下（能推回来 · 不用跨轮）**：只有花费差异。I、E 族关掉 R 多用 34–41% 的请求，准确率不变；OOLONG 到 400 万 token，开不开都能做。
  - **右下（推不回来 · 不用跨轮）**：提示词本身就带着这些信息，不需要任何能力。

**右边卡片 · 按预算选配置：**
- 给 3 个任务族各选 1 种配置，一共 8³ = 512 种组合。
- **产品默认的全开已经在"成本最优"的边界上：¥16.87、0.991。**
- 最好的组合能到 0.998，但要 ¥25.98，**多花 54% 只换来不到 0.7 分**。
- "in-sample"的意思是：用来估计和用来评估的是同一批数据，结果偏乐观，只能看趋势。

**结论句：** 在这里，选择器真正在预测的是**花费**，不是准确率。

### 第 20 页 · 三条结论

**这页在说什么：** 收尾，记住三句话就够。

1. **在信息能重推的任务上，harness 改变的是花费，不是准确率。** 全开反而最便宜（¥16.87 对 ¥32.27），迁移任务的准确率差异被限制在约 2 分以内。
2. **记忆只有在"信息推不回来、又必须保留"时才变成准确率**（0.936 对 0.455），或者在模型自己重推不出来时（强模型 0.975 对 0.710）。
3. **测量的严谨本身就是结果的一部分。** 计分口径、预算、隔离这三件事都改变过结论的边界，所以在扩大规模之前必须先修好。

## 补充：最新发现（演示稿里还没有）

做 v2 计划时，从主实验现有数据里算出了一个关键结果。主实验每格的配额是 40 次请求，几乎没有格子撞到上限，所以可以算出"在 q 次请求以内做对"的比例：

| 任务 · 对比 | 请求预算 | 开 | 关 |
|---|---|---|---|
| T · 记忆 M | 20 次 | 0.62 | 0.10 |
| T · 记忆 M | 40 次（实际配额） | 0.96 | 0.97 |
| I · 持久执行 R | 4 次 | 0.72 | 0.26 |
| E · R（只关 R 对比全开） | 12 次 | 0.77 | 0.20 |

**意思是：** 能力本质上是"效率"。预算宽松时只体现为省钱；预算一紧，就直接体现为准确率。这把"花费翻倍"和"准确率不变"统一成了一件事。

**注意：** 这是看完数据之后才提出的假设，可能高估差距，必须用事先登记好的新实验来确认，不能直接当结论讲。现场被问到"这些能力是不是没用"时，可以用它来回答，但要加一句"初步分析，待确认"。
